# Constrained recursive proof improvement

Question: at equal model budget, does reusing validated proof guidance solve more *new* ownership obligations than a fixed prompt with the same current-task feedback? Improving on repeated CBox alone is not evidence of generalization.

## Pilot

- Use the reference check and the rejection controls before any model trials. The starter checker's whitelist is a deliberately tiny first-stage search space; it validates the evaluation loop but is too easy for a meaningful benchmark on its own.
- On development tasks only, compare (A) one-shot, (B) iterative repair with per-attempt failed obligation labels but no cross-task memory, and (C) iterative repair with carryover of proof guidance. Give B and C the same model, fresh per-task context, attempts, total token budget, and verifier-query budget. Match A's token/total compute budget as closely as practical and report any remaining mismatch. Use multiple paired seeds/tasks; do not claim a general result from one run.
- Across tasks, let C evolve only short instructions and verifier-accepted proof patterns. Initially, candidates are JSON atom selections. Later the permitted surface can include bounded proof scripts or tactic combinations; specifications and executable implementation stay fixed. Failed proof candidates do not become trusted lemmas.
- Lock the checker, initial conditions, transition relation, theorem, external contracts, dependencies, toolchain hash, hidden tasks and metric before the comparison; record their hashes in a manifest. The runner alone invokes verifier commands. Treat model output as untrusted data: strict schema, isolated non-networked scratch, reject edits to frozen inputs, unchecked axioms, admits, forbidden command execution, or altered tests. No external credentials, writes, or deploys in a trial.
- Keep held-out tasks, fixtures and scores out of agent context until candidates and comparisons are frozen. Share training diagnostics but no hidden counterexamples during evolution. Split by task family, not just differently named near-duplicates. An independent reviewer must check contract strength and held-out cases.
- Record checked holdout solve rate as the primary measure, with attempts, tokens, verifier time, errors/unknowns, and pass/fail of all controls. Accept an evolved strategy only after training control regressions pass; retain a previous accepted version for rollback. Run held-out evaluation once after freezing variants, not as feedback. Stop at the fixed budget. If the search space is too narrow to show differences, expand permitted proof moves in a new preregistered run rather than loosening the theorem.

A reasonable next set spans transfer, ordinary drop, and reuse of auxiliary ownership lemmas. Keep the first formal source claim narrower than the benchmark. The present package has only run the abstract certificate and control checks; it has not run an LLM, measured self-improvement, or established that a given proof policy generalizes.
